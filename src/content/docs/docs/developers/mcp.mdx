Tokio has an MCP server, so an AI assistant on the computer running Tokio can do what you'd do in the app: pick TTS voices, create alerts, add sounds from MyInstants, request songs, switch profiles, run the countdown, pause everything and more.

## Turn it on

<Steps>

1. In **Settings → Remote control**, check **Enable remote control**. The overlay server must be on too.

2. In **Settings → AI assistants**, click **Show setup and key**. It shows the MCP address, `http://127.0.0.1:37891/mcp`, and the setup for the assistant you pick under **AI assistant**, with your key in it.

   <Screenshot
     name="settings-mcp"
     alt="The MCP address, and Claude Code picked under AI assistant with its setup"
   />

</Steps>

The MCP server only answers on the computer running Tokio, and every request needs the key. The button next to **Remote control**'s title makes a new key after asking, so update your assistant's setup after using it.

## Connect your assistant

In **Settings → AI assistants**, pick your assistant under **AI assistant** and click its setup to copy it. Where it goes depends on the assistant:

<Tabs>
<TabItem label="Claude Code">

Run it in a terminal:

```sh
claude mcp add --transport http tokio http://127.0.0.1:37891/mcp --header "Authorization: Bearer <key>"
```

</TabItem>
<TabItem label="Codex">

Add it to `~/.codex/config.toml`:

```toml
[mcp_servers.tokio]
url = "http://127.0.0.1:37891/mcp"

[mcp_servers.tokio.http_headers]
Authorization = "Bearer <key>"
```

</TabItem>
<TabItem label="Gemini CLI">

Run it in a terminal. `--scope user` adds Tokio for every folder:

```sh
gemini mcp add --scope user --transport http --header "Authorization: Bearer <key>" tokio http://127.0.0.1:37891/mcp
```

</TabItem>
<TabItem label="Cursor">

Add it to `~/.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "tokio": {
      "url": "http://127.0.0.1:37891/mcp",
      "headers": { "Authorization": "Bearer <key>" }
    }
  }
}
```

</TabItem>
<TabItem label="VS Code">

In VS Code, run **MCP: Open User Configuration** from the Command Palette and add it there:

```json
{
  "servers": {
    "tokio": {
      "type": "http",
      "url": "http://127.0.0.1:37891/mcp",
      "headers": { "Authorization": "Bearer <key>" }
    }
  }
}
```

</TabItem>
<TabItem label="Claude Desktop">

Claude Desktop starts local MCP servers as programs, so it reaches Tokio through [mcp-remote](https://github.com/geelen/mcp-remote), which needs [Node.js](https://nodejs.org). Add it to `claude_desktop_config.json`, then restart Claude Desktop:

```json
{
  "mcpServers": {
    "tokio": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "http://127.0.0.1:37891/mcp",
        "--allow-http",
        "--header",
        "Authorization:${AUTH_HEADER}"
      ],
      "env": { "AUTH_HEADER": "Bearer <key>" }
    }
  }
}
```

Keep `Authorization:` without a space after it: on Windows, Claude Desktop splits the arguments at spaces. Claude Desktop's own connectors can't reach a server on your computer.

</TabItem>
</Tabs>

## What it can do

| Tool                                            | What it's for                                                                                                                                                                                                                                                                                                                                                  |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `get_status`                                    | The connection and each platform's state, the LIVE's numbers, the active features, the pause, the profile, the music, Minecraft, the countdown, the overlay server and app updates                                                                                                                                                                             |
| `get_activity`                                  | The LIVE's recent chat, gifts, follows, shares, Super Fans and joins, subs, Bits, Super Chats, Kicks, raids and redeems, and each platform's top supporters                                                                                                                                                                                                    |

## Several platforms

- Each platform's money comes apart and is never added up: `coins` for TikTok, `bits` for Twitch, `usd` for YouTube's Super Chats in US dollars (`null` until the exchange rates load) and `kicks` for Kick. That goes for the LIVE's numbers, its top supporters and each LIVE in your history. Gifted subs come apart too, as `giftSubs`.
- `get_gifters` ranks one `platform`'s gifters, TikTok's unless it says another, by what they spent or by the subs they gifted (`by: "amount"` or `"subs"`).
- The `platforms` section also holds the name saved for each platform, `username` (TikTok's), `youtube` and `kick`, and saves them without connecting. A platform that's connected keeps the name it's on.
- Fans come from every platform: TikTok's fan club with their fan level, and Twitch's and Kick's subscribers and YouTube's members with their months when known.
- TTS's and music's permissions have Twitch's, YouTube's and Kick's own rules, in `platforms`, with VIPs on Twitch and Kick. Alerts and game actions can react to Kicks and pick VIPs, each with a minimum in its event's own unit, like Bits or Kicks, and an Overlay Studio list can rank who gifted the most subs (`giftsubs`).
- `official_overlays` lists every official overlay with the platforms it works on (`platforms`, `null` for every platform), while Tokio's **Official overlays** shows only the ones for your profile's.

## Good to know

- Tools that delete or overwrite, like removing an alert or a sound, are marked so your assistant asks you first, if it asks for confirmation (most do).
- Chat, names and gift names reach the assistant as viewer data. Tokio tells it not to follow instructions in them, but keep an eye on what it does with them.
- It can't read your keys, open file dialogs, export files, clone a voice, install a Tokio update, turn off the overlay server or change remote control.
- Changes it makes show in Tokio as you'd see your own, notices included.
- From WSL2, `127.0.0.1` reaches Windows only with [mirrored networking](https://learn.microsoft.com/windows/wsl/networking#mirrored-mode-networking).
