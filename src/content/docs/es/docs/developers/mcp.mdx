Tokio tiene un servidor MCP, así que un asistente de IA en la computadora con Tokio puede hacer lo que harías tú en la app: elegir voces de TTS, crear alertas, agregar sonidos de MyInstants, pedir canciones, cambiar de perfil, manejar el temporizador, pausar todo y más.

## Actívalo

<Steps>

1. En **Configuración → Control remoto**, marca **Activar el control remoto**. El servidor de overlays también tiene que estar activado.

2. En **Configuración → Asistentes de IA**, haz clic en **Mostrar configuración y clave**. Ahí están la dirección MCP, `http://127.0.0.1:37891/mcp`, y la configuración del asistente que elijas en **Asistente de IA**, con tu clave.

   <Screenshot
     name="settings-mcp"
     alt="La dirección MCP, y Claude Code elegido en Asistente de IA con su configuración"
   />

</Steps>

El servidor MCP solo responde en la computadora con Tokio, y cada solicitud necesita la clave. El botón junto al título de **Control remoto** crea una clave nueva después de preguntar, así que actualiza la configuración de tu asistente después de usarlo.

## Conecta tu asistente

En **Configuración → Asistentes de IA**, elige tu asistente en **Asistente de IA** y haz clic en su configuración para copiarla. Dónde va depende del asistente:

<Tabs>
<TabItem label="Claude Code">

Ejecútalo en una terminal:

```sh
claude mcp add --transport http tokio http://127.0.0.1:37891/mcp --header "Authorization: Bearer <clave>"
```

</TabItem>
<TabItem label="Codex">

Agrégalo a `~/.codex/config.toml`:

```toml
[mcp_servers.tokio]
url = "http://127.0.0.1:37891/mcp"

[mcp_servers.tokio.http_headers]
Authorization = "Bearer <clave>"
```

</TabItem>
<TabItem label="Gemini CLI">

Ejecútalo en una terminal. `--scope user` agrega Tokio para todas las carpetas:

```sh
gemini mcp add --scope user --transport http --header "Authorization: Bearer <clave>" tokio http://127.0.0.1:37891/mcp
```

</TabItem>
<TabItem label="Cursor">

Agrégalo a `~/.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "tokio": {
      "url": "http://127.0.0.1:37891/mcp",
      "headers": { "Authorization": "Bearer <clave>" }
    }
  }
}
```

</TabItem>
<TabItem label="VS Code">

En VS Code, ejecuta **MCP: Open User Configuration** desde la paleta de comandos y agrégalo ahí:

```json
{
  "servers": {
    "tokio": {
      "type": "http",
      "url": "http://127.0.0.1:37891/mcp",
      "headers": { "Authorization": "Bearer <clave>" }
    }
  }
}
```

</TabItem>
<TabItem label="Claude Desktop">

Claude Desktop inicia los servidores MCP locales como programas, así que llega a Tokio a través de [mcp-remote](https://github.com/geelen/mcp-remote), que necesita [Node.js](https://nodejs.org). Agrégalo a `claude_desktop_config.json` y reinicia Claude Desktop:

```json
{
  "mcpServers": {
    "tokio": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "http://127.0.0.1:37891/mcp",
        "--allow-http",
        "--header",
        "Authorization:${AUTH_HEADER}"
      ],
      "env": { "AUTH_HEADER": "Bearer <clave>" }
    }
  }
}
```

Deja `Authorization:` sin espacio después: en Windows, Claude Desktop separa los argumentos en los espacios. Los conectores de Claude Desktop no llegan a un servidor en tu computadora.

</TabItem>
</Tabs>

## Varias plataformas

- El dinero de cada plataforma llega aparte y nunca se suma: `coins` para TikTok, `bits` para Twitch, `usd` para los Super Chats de YouTube en dólares estadounidenses (`null` hasta que cargan los tipos de cambio), `jewels` para los Regalos de YouTube y `kicks` para Kick. Así vienen los números del LIVE, quienes más enviaron y cada LIVE de tu historial. Las suscripciones regaladas también llegan aparte, como `giftSubs`.
- `get_gifters` ordena a quienes más enviaron en una plataforma (`platform`, TikTok si no dice otra), por lo que gastaron o por las suscripciones que regalaron (`by: "amount"` o `"subs"`, y en YouTube `"jewels"`).
- La sección `platforms` también guarda el nombre de cada plataforma, `username` (el de TikTok), `youtube` y `kick`, y los guarda sin conectarse. Una plataforma conectada conserva el nombre con el que está conectada.
- Los fans llegan de todas las plataformas: el club de fans de TikTok con su nivel de fan, y los suscriptores de Twitch y de Kick y los miembros de YouTube con sus meses cuando se saben.
- Los permisos del TTS y de la música tienen reglas propias para Twitch, YouTube y Kick, en `platforms`, con VIPs en Twitch y Kick. Las alertas y las acciones de juego pueden reaccionar a los Kicks y elegir VIPs, cada una con un mínimo en la unidad de su evento, como Bits o Kicks, y una lista de Overlay Studio puede ordenar a quienes más suscripciones regalaron (`giftsubs`).
- `official_overlays` lista todos los overlays oficiales con las plataformas en las que funcionan (`platforms`, `null` para todas), mientras que **Overlays oficiales** en Tokio muestra solo los de las plataformas de tu perfil.

## Bueno saber

- Las herramientas que borran o reemplazan, como quitar una alerta o un sonido, están marcadas para que tu asistente te pregunte antes, si pide confirmación (la mayoría lo hace).
- El chat, los nombres y los nombres de los regalos llegan al asistente como datos de los espectadores. Tokio le indica que no siga instrucciones que vengan en ellos, pero fíjate en lo que hace con ellos.
- No puede leer tus claves, abrir diálogos de archivos, exportar archivos, clonar una voz, instalar una actualización de Tokio, apagar el servidor de overlays ni cambiar el control remoto.
- Los cambios que hace se ven en Tokio como los tuyos, con sus avisos.
- Desde WSL2, `127.0.0.1` llega a Windows solo con las [redes en modo reflejado](https://learn.microsoft.com/windows/wsl/networking#mirrored-mode-networking).
